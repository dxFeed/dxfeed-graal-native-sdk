# NetTestApi: a publisher over the dxFeed Java API

`NetTestApi p` publishes generated Trade or TimeAndSale events through the `DXPublisher` of a dxFeed `DXEndpoint`
(role `PUBLISHER` or `STREAM_PUBLISHER`) and prints the statistics of the QD tool `NetTest p` (qds-tools). It is the
Java counterpart of the C tool [NetTest](../../src/main/c/src/apps/NetTest/README.md) and takes the same command line,
so that the same publishing can be measured three ways with one mux, consumer and parsers: QD NetTest (records), this
tool (dxFeed events in Java) and the C tool (dxFeed events through the SDK).

It is a tool of QD's `Tools` (`NetTestApi`, next to `NetTest`), in the package `com.devexperts.qd.tools`, and reuses
the symbols, the rate limiter and the statistics of QD NetTest without changing QD. It is a separate Maven project, not
a module of the SDK build and not part of the SDK archives.

## Getting the tool

It is deployed with every SDK release as `com.dxfeed:graal-native-sdk-nettest:<version>`, to the same repository as
the SDK archives: the jar of the tool and the all-in-one jar with QD (classifier `all`). Its QD version is the
`qd.version` of the SDK release. To build it from the sources (JDK 21 or later):

```shell
mvn -f tools/nettest/pom.xml package
```

The all-in-one jar is `tools/nettest/target/graal-native-sdk-nettest-0-SNAPSHOT-all.jar`. Run it with JDK 21 or later:

```shell
java -jar graal-native-sdk-nettest-<version>-all.jar NetTestApi p :6666 -S 50000 -r */1M --duration 7m
java -jar graal-native-sdk-nettest-<version>-all.jar Help NetTestApi
```

The all-in-one jar holds the other QD tools as well (`Help contents` lists them), so QD NetTest runs from it too.

## Command line

```text
NetTestApi p <address> -S <symbols> [-C <n>] [-r */<rate>] [-s <period>] [-n <name>] [--batch <n>]
           [--event Trade|TimeAndSale] [--reuse] [--role PUBLISHER|STREAM_PUBLISHER] [--duration <time>]
           [-D<key>=<value>...]
```

The options have the meaning and the limits of the C tool:

| Option                   | Meaning                                                                                       |
|--------------------------|-----------------------------------------------------------------------------------------------|
| `<address>`              | `:port` listens (the mux connects to it), `host:port` connects to a listening peer           |
| `-S <total>@<file>`      | the first `<total>` symbols of an IPF file                                                    |
| `-S <total>`             | `<total>` distinct symbols generated by QD NetTest                                            |
| `-C <n>`                 | instances: endpoints `NetTest.1` ... `NetTest.<n>`, one generator thread each, the whole pool each; not above 1 with `:port` |
| `-r */<rate>`            | the total rate of all instances in records per second, with `k`, `M` or `G`; without it the generators run flat out |
| `-s <period>`            | the statistics period, default `10s` (`ms`, `s`, `m`)                                         |
| `-n <name>`              | the name in the statistics line, default `NetTest`                                            |
| `--batch <n>`            | events per `publishEvents` call, default 100                                                  |
| `--event`                | `Trade` (default) or `TimeAndSale`                                                            |
| `--reuse`                | republish the pre-built events; without it every batch is made of new event objects, as an application that creates its events would do |
| `--role`                 | the role of the endpoints: `PUBLISHER` (default) or `STREAM_PUBLISHER`; this tool only        |
| `--duration <time>`      | end the run after this time; Ctrl+C (SIGINT, SIGTERM) ends it at once, a second Ctrl+C halts the JVM |
| `-D<key>=<value>`        | set a system property before the first endpoint, for example `-Ddxscheme.nanoTime=true`       |

Not taken: `--legacy` (the C tool's deprecated publishing call), the `-X` and `-XX:` options (JVM options: put them
before `-jar`, see [Differences from the C tool](#differences-from-the-c-tool)), and the QD NetTest flags that the C
tool does not have (`-c`, `-w`, `{len,max}` and `/r`, `/s` in `-S`, a bucket `;<time>` in `-r`). They exit with 2
and name the argument. Of several `-r`, the last one counts.

Every event carries the current time: `setTimeNanos()` and a 22-bit sequence per instance (`setSequence()`), as the
C tool fills `time_sequence` (Trade) or `index` (TimeAndSale) and `time_nano_part`. A consumer computes the business
lag from it as for QD NetTest's own records.

Exit codes: 0 after `--duration` or Ctrl+C, 2 for invalid arguments, 1 for a failed start (unreadable IPF file, failed
endpoint, a `:port` that does not start listening within 3 s, for example because it is in use) or a failed publishing
call. Connecting is asynchronous: a `host:port` without a listener is not an error, the tool runs and reports
`connections 0` until a peer is there.

## Statistics

Every period the tool logs:

```text
I 261113 141024.007 {*NetTestApiProducerSide-NetTest*} data 1,767,033 rps, lag 57 us, instances 1, connections 1
    NetTest.1 data 1,767,033 rps, lag 57 us
```

- `data`: events handed to `publishEvents` per second.
- `lag`: the time to fill a batch and publish it, weighted by its events; the wait for the rate limiter is not
  included.
- `connections`: open connections of all instances' connectors.

The line is QD NetTest's own (`NetTestStatisticsCollector`), so the parsers of QD NetTest read it.

## Differences from the C tool

- The label is `NetTestApiProducerSide` instead of `NetTestProducerSide` (a parser that matches the label must accept
  both), and the line has the prefix of QD's log (`I <date> <time>`). QD logs to stderr when the output is redirected.
- The statistics are a task of the QDS monitoring of the first endpoint, so `NetTest.1` also logs its monitoring lines
  (subscription, storage, the read and write rates of every connector) every period; the other endpoints log none. The
  C tool logs them only with `-Dmonitoring.stat`. No last block is printed when the run stops.
- With `-r` a generator takes from QD's rate limiter what is available, up to `--batch`, as QD NetTest does, so a
  batch may be shorter than `--batch`; the C tool waits for a whole batch.
- The events are Java objects in a JVM with its JIT and GC, not in a Graal isolate: warm the run up before you read the
  numbers, and set the heap and the GC with JVM options: `java -Xmx2g -XX:+UseParallelGC -jar ... NetTestApi ...`.
- QD and MARS log their start (`Using QDS-...`, the multicast time synchronization), as every QD tool does.

## Running against QD NetTest

The consumer must subscribe to the same record and symbols. A `PUBLISHER` endpoint feeds Trade to the ticker and the
stream contracts, and TimeAndSale to the stream and the history contracts. With the default `--event Trade`:

```shell
java -jar graal-native-sdk-nettest-<version>-all.jar NetTestApi p :6666 -S 50000 -r */1M -s 10s --duration 7m
java -Dcom.devexperts.qd.tools.NetTest.record=Trade -jar graal-native-sdk-nettest-<version>-all.jar NetTest c localhost:6666 -S 50000
```

For `--event TimeAndSale` drop the property (TimeAndSale is QD NetTest's default record) and give the consumer
`-c stream`: the default ticker consumer gets no TimeAndSale and reports `data 0 rps`. With
`--role STREAM_PUBLISHER` every event goes to the stream contract only, so the consumer needs `-c stream` for either
event. Against a mux, run the publisher with `:6666` and point the mux's distributor connector at it.
