Detailed Description

Subscriptions to the events of a feed: the event types and the symbols, the listeners of events and of the changes of the subscription, the executor, the aggregation period and the batch limit.

A subscription (dxfg_subscription_t) is interested in the events whose type is in its set of event types and whose symbol is in its set of symbols. The event types are set when the subscription is created, the symbols can be changed at any time. A subscription created by dxfg_DXFeedSubscription_new() or dxfg_DXFeedSubscription_new2() is detached: it is not attached to any feed and receives no events. Attach it with dxfg_DXFeedSubscription_attach(). A subscription created by a feed (e.g. dxfg_DXFeed_createSubscription()) is attached to that feed. A time series subscription (dxfg_time_series_subscription_t) is a subscription for the time series events that is created by a feed with dxfg_DXFeed_createTimeSeriesSubscription().

The events are passed to the event listeners (see dxfg_DXFeedEventListener_new()) by the executor of the subscription, one batch after another. Add the event listeners before the symbols: the listeners receive the last events of the symbols that were added. The changes of the subscription are passed to the change listeners (see dxfg_ObservableSubscriptionChangeListener_new()).

A subscription is closed only by dxfg_DXFeedSubscription_close(): releasing its handle does not close it. A subscription that stays attached to a feed keeps receiving events and is not freed, so close it when it is not needed any more.

The ownership rules (handles, strings, lists) are the ones of the group Javac. A symbol or a list that is passed to a function is only read by the SDK: the caller keeps its ownership. A list that a function returns is released by the caller with the function given in the description of the function. The value that a function returns on error is given in its @return. dxfg_get_and_clear_thread_exception_t() gives the exception.

◆ dxfg_feed_event_listener_function

typedef void(*) dxfg_feed_event_listener_function(graal_isolatethread_t *thread, dxfg_event_type_list *events, void *user_data)

The function of a dxfg_feed_event_listener_t: called when events are received.

The function is called by a thread of the executor of the subscription (the default executor of the feed's endpoint, or the executor set by dxfg_DXFeedSubscription_setExecutor()), not by the thread that added the listener. The calls for one subscription do not overlap: the next batch of events is passed after the function returns for the previous one. The number of events in a batch is limited by the events batch limit (see dxfg_DXFeedSubscription_setEventsBatchLimit()).

The list and the events belong to the SDK: it frees them (with their strings) after the function returns. Do not release them, copy what you need to keep.

Java: DXFeedEventListener.eventsReceived(List).

Parameters
[in]threadThe current GraalVM Isolate's thread.
[in]eventsThe received events.
[in]user_dataThe pointer that was passed to dxfg_DXFeedEventListener_new(); the SDK does not use it.

Adds the change listener to the subscription.

Create the listener with dxfg_ObservableSubscriptionChangeListener_new(). If the listener was not added yet, is added to an open subscription and the subscription has symbols, the listener is notified immediately of the existing symbols (its symbolsAdded function) on the calling thread before the function returns. After that it is notified of every change on the thread that changes the subscription. The calls of the listener for one subscription do not overlap. Adding a listener that is already added, or to a closed subscription, does nothing.

◆ dxfg_DXFeedSubscription_close()

int32_t dxfg_DXFeedSubscription_close ( graal_isolatethread_t * thread,
dxfg_subscription_t * sub )

Closes the subscription and makes it permanently detached from all feeds.

The subscription removes all its event listeners and change listeners and does not accept new ones. Every change listener is notified of the close (its subscriptionClosed function, see dxfg_ObservableSubscriptionChangeListener_new()) on the calling thread before the function returns. The handle is not released: release it with dxfg_JavaObjectHandler_release(). Closing a closed subscription does nothing.

An event listener may still receive one more batch of events after the function returns. To be sure that its function is not called anymore, release the listener (dxfg_JavaObjectHandler_release()) or deactivate it (dxfg_NativeListener_deactivate()).

Parameters
[in]threadThe current GraalVM Isolate's thread.
[in]subThe subscription handle.
Returns
DXFG_EXECUTE_SUCCESSFULLY (0) on successful function execution or DXFG_EXECUTE_FAIL (-1) on error. Use dxfg_get_and_clear_thread_exception_t() to determine if an exception was thrown.

Java: DXFeedSubscription.close().
