Detailed Description

The feed (Java DXFeed), its subscriptions, the requests of events, and the promises that the requests return.

The ownership rules of the handles, the strings and the lists are described in the group Javac. The events that a function returns are released with dxfg_EventType_release(), the lists of events with dxfg_CList_EventType_release().

In this header a function that returns an int32_t status returns DXFG_EXECUTE_SUCCESSFULLY (0) or DXFG_EXECUTE_FAIL (-1) on error, and a function that returns a pointer returns NULL on error, except dxfg_Promise_getException() that returns (dxfg_exception_t *)-1. The functions that tell the state of a promise return 1, 0 or -1 on error.

A promise is the result of a request that completes later. The functions that start a request return a handle of the promise: wait for it (dxfg_Promise_await2()) or add a handler (dxfg_Promise_whenDone()), then read the result (dxfg_Promise_EventType_getResult(), dxfg_Promise_List_EventType_getResult()) and release the handle.

◆ dxfg_promise_handler_function

typedef void(*) dxfg_promise_handler_function(graal_isolatethread_t *thread, dxfg_promise_t *promise, void *user_data)

The function that is called when a promise is done.

It is added by dxfg_Promise_whenDone() or dxfg_Promise_whenDoneAsync() and called exactly once, when the promise completes normally, completes exceptionally or is cancelled. The thread that calls it is described in dxfg_Promise_whenDone() and dxfg_Promise_whenDoneAsync(). The function can call the SDK functions with the given thread, e.g. read the result with dxfg_Promise_EventType_getResult().

promise is the pointer that was passed to dxfg_Promise_whenDone() or dxfg_Promise_whenDoneAsync(): the caller owns it, the SDK does not release it and does not copy it, so the caller must keep it valid until the function has been called.

Java: PromiseHandler.promiseDone(Promise).

Parameters
[in]threadThe current GraalVM Isolate's thread.
[in]promiseThe promise that is done: the pointer given when the function was added.
[in]user_dataThe pointer that was passed with the function as is; the SDK does not use it.

◆ dxfg_DXFeed_getIndexedEventsIfSubscribed()

dxfg_event_type_list * dxfg_DXFeed_getIndexedEventsIfSubscribed ( graal_isolatethread_t * thread,
dxfg_feed_t * feed,
dxfg_event_clazz_t eventClazz,
dxfg_symbol_t * symbol,
const char * source )

Returns the indexed events for the event class, symbol and source if there is a subscription for them.

Works only for the indexed events. The function does not make remote calls, it reads the local cache of the feed. The events are in the cache only if an attached subscription is subscribed to the event class, symbol and source (a subscription can also be defined by the endpoint properties). The events are ordered by index, their event flags are always 0. The list is not a consistent snapshot: use dxfg_DXFeed_getIndexedEventsPromise() for it. With the DXFG_ENDPOINT_ROLE_STREAM_FEED role there are never events.

If there is no subscription (Java returns null) or the events have not arrived yet, the result is an empty list (size is 0, elements is NULL); the two cases cannot be told apart by the result. The empty list must be released as well.

◆ dxfg_DXFeed_getIndexedEventsPromise()

dxfg_promise_events_t * dxfg_DXFeed_getIndexedEventsPromise ( graal_isolatethread_t * thread,
dxfg_feed_t * feed,
dxfg_event_clazz_t eventClazz,
dxfg_symbol_t * symbol,
dxfg_indexed_event_source_t * source )

Requests the indexed events for the event class, symbol and source and returns the promise of the result.

Works only for the indexed events. The promise completes with a new list of new events ordered by index; read it with dxfg_Promise_List_EventType_getResult(). The promise completes only when a consistent snapshot has been received; the event flags of the events are always 0, so the list must not be passed to dxfg_DXPublisher_publishEvents(). The request is sent to the uplink data provider; it works also without a subscription. The result is a snapshot: use a subscription for the updates in real time. The promise is cancelled when the endpoint of the feed is closed. If the data is not available for a transient reason (no subscription, no connection to the uplink, etc.), the promise completes when the issue is resolved, which may take arbitrarily long: wait with a timeout (dxfg_Promise_await2()). If the data is permanently not available (not supported), the promise completes exceptionally with IllegalArgumentException. With the DXFG_ENDPOINT_ROLE_STREAM_FEED role the promise completes exceptionally.

Use the source with the identifier 0 (the default source) for the events that have no multiple sources (e.g., Series) and an order source for the events with multiple sources (Order, etc.). The synthetic order sources are not supported.

A handler added by dxfg_Promise_whenDone() is called by a thread of the executor of the endpoint of the feed (see dxfg_DXEndpoint_Builder_withExecutor()).

Adds a handler that is called when the promise is done.

The handler is called exactly once: when the promise completes normally, completes exceptionally or is cancelled. There is no way to remove it. If the promise is already done, the handler is called before the function returns, by the calling thread. Otherwise it is called by the thread that completes or cancels the promise. For the promises of the feed requests it is a thread of the executor of the endpoint of the feed; for the others it is the thread that called dxfg_Promise_cancel(), dxfg_Promise_EventType_complete(), etc., or the thread that waits with dxfg_Promise_await2() when its timeout cancels the promise. Use dxfg_Promise_whenDoneAsync() to run the handler on a given executor.

The handler receives the pointer promise that is passed here: the SDK does not copy or release the structure, so it must stay valid until the handler has been called. user_data is passed to the handler as is, the SDK does not use it.

Adds a handler that is called by the given executor when the promise is done.

As dxfg_Promise_whenDone(), but the handler is never called by the calling thread or the thread that completes the promise: it is called by a thread of the executor, as a task that the SDK gives to it. The handler is called exactly once, and there is no way to remove it. The pointer promise must stay valid until the handler has been called, see dxfg_Promise_whenDone().

The executor handle is only read during the call: the caller keeps it and may release it after the function returns (the promise keeps the executor object).

◆ dxfg_Promises_allOf()

dxfg_promise_t * dxfg_Promises_allOf ( graal_isolatethread_t * thread,
dxfg_promise_list * promises )

Creates a promise that is done when all the given promises are done.

The given promises may complete normally or exceptionally: the result of the new promise is null, their results are not reflected in it, so inspect them one by one. If the list is empty, the new promise is already completed. When the new promise completes for any reason (it is cancelled, for example), all the given promises are cancelled. A NULL list is an empty list; a NULL promise in the list is an error.
