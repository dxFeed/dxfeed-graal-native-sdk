#define DXFG_V4_ADVANCED_REVISION   ((int32_t)1)

The advanced revision of these headers: the revision of the experimental functions that a wrapper is built for.

The revision is incremented when an experimental function changes incompatibly (see The v4 functions). A wrapper compares it with dxfg_v4_system_get_advanced_revision() at start-up: it binds the stable functions always, and the experimental ones only when the revisions are equal.

◆ dxfg_v4_system_close_all_and_await_termination()

int32_t dxfg_v4_system_close_all_and_await_termination ( graal_isolatethread_t * thread)

Closes all the endpoints and instrument profile connections created through the SDK in this isolate and waits for the termination of the endpoints.

It includes the default endpoints of dxfg_v4_DXEndpoint_getInstance(), dxfg_v4_DXFeed_getInstance(), dxfg_v4_DXPublisher_getInstance() and dxfg_v4_OnDemandService_getInstance(). The handles of the objects stay valid and must be released as usual.

Call it before graal_tear_down_isolate() (or before the process exits): the threads of an open endpoint ("DXEndpoint-DXExecutorThread-N", etc.) do not stop on Thread.interrupt(), so graal_tear_down_isolate() waits for them forever while any endpoint is open. The function does not stop the calls of the native listeners: dxfg_v4_system_shutdown() stops them first and then calls this function. To find the threads that block the tear-down, pass the -XX:TearDownWarningSeconds=<seconds> option in graal_create_isolate_params_t.argv.

The function blocks the calling thread until the endpoints are terminated: do not call it from a listener of an endpoint, it would wait for the notification that is calling it. The endpoints and connections created after the call are not closed by it. The function is a function of the SDK: there is no QD method that it calls.

Parameters
[in]threadThe current GraalVM Isolate's thread.
Returns
DXFG_EXECUTE_SUCCESSFULLY (0) on successful function execution or DXFG_EXECUTE_FAIL (-1) on error (also if the waiting thread is interrupted). Use dxfg_v4_get_and_clear_thread_exception() to determine if an exception was thrown.

◆ dxfg_v4_system_set_property()

int32_t dxfg_v4_system_set_property ( graal_isolatethread_t * thread,
const char * key,
const char * value )

Sets the Java system property indicated by the specified key.

The property is a property of the Java system of the isolate (System.setProperty): the QD library and the SDK read their settings from it, e.g. the properties of the endpoints (dxfeed.address, dxfeed.threadPoolSize, ...) and of the logging (log.className, log.level, see the group Logging). The properties that configure endpoints must be set before the first endpoint is created. For example:

  • com.dxfeed.sdk.TimeSyncTracker.enable = true enables the QD TimeSyncTracker, which sends UDP multicast packets (239.192.51.45:5145 by default, see com.devexperts.qd.tools.TimeSyncTracker.addr and .port) to compare the clocks of the hosts. The SDK disables it by default.

Java: System.setProperty(String, String).

[in]threadThe current GraalVM Isolate's thread.
[in]keyThe name of the property, a NUL-terminated UTF-8 string; the SDK copies it. It must not be NULL or empty.
[in]valueThe value of the property, a NUL-terminated UTF-8 string; the SDK copies it. It must not be NULL.
Returns
DXFG_EXECUTE_SUCCESSFULLY (0) on successful function execution or DXFG_EXECUTE_FAIL (-1) on error. Use dxfg_v4_get_and_clear_thread_exception() to determine if an exception was thrown.

◆ dxfg_v4_system_shutdown()

int32_t dxfg_v4_system_shutdown ( graal_isolatethread_t * thread)

Stops the calls of all the native listeners of this isolate, then closes all the endpoints and instrument profile connections and waits for the termination of the endpoints.

The function calls dxfg_v4_NativeListener_deactivateAll(), which also closes the event queues, and then dxfg_v4_system_close_all_and_await_termination(), so that no listener is called and no poll waits while the endpoints are closed. Both steps wait without a limit; like them, the function is irreversible: the listeners created afterwards are never called, the endpoints created afterwards are not closed by it.

Recommended shutdown sequence:

  1. dxfg_v4_system_shutdown(). After it returns, no listener's function is called and none of its calls is in progress, so the user data of the listeners can be freed; every poll of an event queue returns DXFG_EVENT_QUEUE_CLOSED, so the polling threads can leave the SDK.
  2. Release the remaining handles (dxfg_v4_JavaObjectHandler_release()), the listeners among them.
  3. graal_tear_down_isolate(), if the isolate is torn down at all; the process may also just exit.

Call it in a normal context of the application: not while holding the locks that the listeners' functions may take (it may deadlock), not from a listener of an endpoint (it would wait for the notification that is calling it), and not from an exit handler of a DLL (DLL_PROCESS_DETACH, a destructor of a static object of a DLL): there the loader lock is held, and a listener's call that waits for it never finishes.

Parameters
[in]threadThe current GraalVM Isolate's thread.
Returns
DXFG_EXECUTE_SUCCESSFULLY (0) on successful function execution or DXFG_EXECUTE_FAIL (-1) on error (also if the waiting thread is interrupted while waiting for the endpoints). Use dxfg_v4_get_and_clear_thread_exception() to determine if an exception was thrown.
