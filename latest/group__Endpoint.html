Detailed Description

The endpoint (Java DXEndpoint): a connection to a data feed or to a publisher, its role and state, and the access to its feed and publisher.

The ownership rules of the handles, the strings and the lists are described in the group Javac.

A typical life cycle of an endpoint:

  1. Create it with dxfg_DXEndpoint_Builder_build() (see the group Endpoint builder), dxfg_DXEndpoint_create() or dxfg_DXEndpoint_create2(). The default endpoint of the process is returned by dxfg_DXEndpoint_getInstance().
  2. Optionally add a state change listener (dxfg_PropertyChangeListener_new(), dxfg_DXEndpoint_addStateChangeListener()) and set the credentials (dxfg_DXEndpoint_user(), dxfg_DXEndpoint_password()).
  3. Connect with dxfg_DXEndpoint_connect() and take the feed (dxfg_DXEndpoint_getFeed()) or the publisher (dxfg_DXEndpoint_getPublisher()).
  4. Close it with dxfg_DXEndpoint_close() or dxfg_DXEndpoint_closeAndAwaitTermination() and release all the handles with dxfg_JavaObjectHandler_release(). Releasing a handle does not close the endpoint. An endpoint that stays open keeps its threads running: close all of them with dxfg_system_close_all_and_await_termination() before graal_tear_down_isolate().

◆ dxfg_endpoint_state_change_listener_func

typedef void(*) dxfg_endpoint_state_change_listener_func(graal_isolatethread_t *thread, dxfg_endpoint_state_t old_state, dxfg_endpoint_state_t new_state, void *user_data)

The function of a dxfg_endpoint_state_change_listener_t: called when the state of the endpoint changes.

The function is called by a thread of the executor of the endpoint (the default thread pool or the executor that was set with dxfg_DXEndpoint_Builder_withExecutor()), not by the thread that added the listener or changed the state. A change is reported from the last reported state to the current one, so the fast changes are coalesced (see dxfg_DXEndpoint_addStateChangeListener()). The states are passed by value, there is nothing to release. Do not call dxfg_DXEndpoint_closeAndAwaitTermination() of the same endpoint from the function.

Java: PropertyChangeListener.propertyChange(PropertyChangeEvent).

Java: DXEndpoint.Role.

Javadoc

Enumerator
DXFG_ENDPOINT_ROLE_FEED 

Connects to a remote data feed provider; optimized for real-time or delayed data. The default role. The events are conflated when the event processing cannot keep up.

DXFG_ENDPOINT_ROLE_ON_DEMAND_FEED 

Similar to DXFG_ENDPOINT_ROLE_FEED, but only for the replay of historical data with the on-demand service: it is not connected to the data provider until the replay is started. It cannot be connected to an ordinary data feed.

DXFG_ENDPOINT_ROLE_STREAM_FEED 

Similar to DXFG_ENDPOINT_ROLE_FEED, but designed for bulk parsing of data from files: the events are not conflated and not skipped and are processed as fast as possible. The last event requests do not work in this role.

DXFG_ENDPOINT_ROLE_PUBLISHER 

Connects to a remote publisher hub or creates a publisher on the local host; the publisher of the endpoint publishes the events to all the connected feeds. The last event requests and the time series subscription do not work in this role.

DXFG_ENDPOINT_ROLE_STREAM_PUBLISHER 

Similar to DXFG_ENDPOINT_ROLE_PUBLISHER, but designed for bulk publishing: the events are not conflated and not skipped and are processed as fast as possible.

DXFG_ENDPOINT_ROLE_LOCAL_HUB 

A local hub without the network connections: the events published with the publisher of the endpoint are delivered to the feed of the same endpoint only.

int32_t dxfg_DXEndpoint_addStateChangeListener ( graal_isolatethread_t * thread,
dxfg_endpoint_t * endpoint,
dxfg_endpoint_state_change_listener_t * listener )

Adds the state change listener (see dxfg_PropertyChangeListener_new()).

The state changes are delivered by a single task on the endpoint's executor that reports the change from the last reported state to the current one, so the fast changes are coalesced (e.g. DXFG_ENDPOINT_STATE_NOT_CONNECTED -> DXFG_ENDPOINT_STATE_CONNECTED without DXFG_ENDPOINT_STATE_CONNECTING). A notification may come after dxfg_DXEndpoint_close() or dxfg_DXEndpoint_removeStateChangeListener() returns.

The listener stays added until it is removed with dxfg_DXEndpoint_removeStateChangeListener(); releasing the last handle of the listener only deactivates it.

int32_t dxfg_DXEndpoint_awaitNotConnected ( graal_isolatethread_t * thread,
dxfg_endpoint_t * endpoint )

Waits until the state of the endpoint becomes DXFG_ENDPOINT_STATE_NOT_CONNECTED or DXFG_ENDPOINT_STATE_CLOSED.

It is the signal that the files opened with dxfg_DXEndpoint_connect() (file:... addresses) were finished reading, but not necessarily completely processed by the subscription listeners. Call dxfg_DXEndpoint_closeAndAwaitTermination() after it returns to make sure that all the processing has completed.

The function blocks the calling thread. With a single-threaded executor of the endpoint, do not call it from the executor's thread (e.g. from a listener): it would wait forever.

◆ dxfg_DXEndpoint_close()

int32_t dxfg_DXEndpoint_close ( graal_isolatethread_t * thread,
dxfg_endpoint_t * endpoint )

Closes the endpoint: disconnects it and releases its resources. The endpoint cannot be used after that.

The state of the endpoint becomes DXFG_ENDPOINT_STATE_CLOSED immediately.

The function does not wait for the notifications that are already scheduled: a state change listener (including the change to DXFG_ENDPOINT_STATE_CLOSED) or an event listener may still be called after it returns. Use dxfg_DXEndpoint_closeAndAwaitTermination() to wait for them, or dxfg_JavaObjectHandler_release() of the listener to stop its calls (see dxfg_JavaObjectHandler_release()).

Closes the endpoint and waits until all the data processing and the scheduled notifications are completed.

It does the same as dxfg_DXEndpoint_close() and blocks until the outstanding tasks of the endpoint are finished. It is designed for the DXFG_ENDPOINT_ROLE_STREAM_FEED role, after dxfg_DXEndpoint_awaitNotConnected() returns, to make sure that a file was completely processed.

◆ dxfg_DXEndpoint_connect()

int32_t dxfg_DXEndpoint_connect ( graal_isolatethread_t * thread,
dxfg_endpoint_t * endpoint,
const char * address )

Connects the endpoint to the remote address.

The previously established connections are closed if the new address is different from the old one. The function does nothing if the address does not change or if the endpoint is closed. Otherwise, the state of the endpoint immediately becomes DXFG_ENDPOINT_STATE_CONNECTING.

The function does not wait until the connection is established: it is established asynchronously. It waits only until the state change listeners have processed the change to DXFG_ENDPOINT_STATE_CONNECTING.

The address string comes with the market data vendor agreement, for example host:port to connect to a server with TCP/IP, or :port to listen for a connection. A malformed address or a NULL address is an error. For the services that require credentials call dxfg_DXEndpoint_user() and dxfg_DXEndpoint_password() first.

◆ dxfg_DXEndpoint_executor()

int32_t dxfg_DXEndpoint_executor ( graal_isolatethread_t * thread,
dxfg_endpoint_t * endpoint,
dxfg_executor_t * executor )

Changes the executor of the endpoint's notifications.

The executor runs all the asynchronous interaction with the user code: event processing, state changes, etc.

Call it before dxfg_DXEndpoint_getFeed() (and before the other functions that use the endpoint's feed, e.g. dxfg_OnDemandService_getInstance2()). Otherwise, the feed keeps using the default executor, which is shut down, and the last events requests (dxfg_DXFeed_getLastEventPromise(), etc.) never complete (a RejectedExecutionException is logged).

The executor must not reject the submitted tasks. A NULL executor is an error.

◆ dxfg_DXEndpoint_reconnect()

int32_t dxfg_DXEndpoint_reconnect ( graal_isolatethread_t * thread,
dxfg_endpoint_t * endpoint )

Terminates all the network connections of the endpoint and initiates connecting again with the same address.

It works like dxfg_DXEndpoint_disconnect() followed by dxfg_DXEndpoint_connect() with the current address, but the internal resources may be reused. A connection with several target addresses tries to switch to an alternative address; the configured reconnect timeouts apply.

The function does not connect an endpoint that was not connected with dxfg_DXEndpoint_connect() or was disconnected with dxfg_DXEndpoint_disconnect(). Whether a state change listener sees the intermediate DXFG_ENDPOINT_STATE_NOT_CONNECTED state is not specified.

Releasing the last handle of the listener with dxfg_JavaObjectHandler_release() (or dxfg_NativeListener_deactivate()) stops the calls of the function: after the release returns the function is not running and is not called anymore, so the user data can be freed.
