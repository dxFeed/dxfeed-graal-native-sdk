◆ dxfg_v4_endpoint_state_change_listener_func

typedef dxfg_endpoint_state_change_listener_func dxfg_v4_endpoint_state_change_listener_func

The function of a dxfg_endpoint_state_change_listener_t: called when the state of the endpoint changes.

The function is called by a thread of the executor of the endpoint (the default thread pool or the executor that was set with dxfg_DXEndpoint_Builder_withExecutor()), not by the thread that added the listener or changed the state. A change is reported from the last reported state to the current one, so the fast changes are coalesced (see dxfg_DXEndpoint_addStateChangeListener()). The states are passed by value, there is nothing to release. Do not call dxfg_DXEndpoint_closeAndAwaitTermination() of the same endpoint from the function.

Java: PropertyChangeListener.propertyChange(PropertyChangeEvent).

Parameters
[in]threadThe current GraalVM Isolate's thread.
[in]old_stateThe previous state of the endpoint.
[in]new_stateThe new state of the endpoint.
[in]user_dataThe pointer that was passed to dxfg_PropertyChangeListener_new(); the SDK does not use it.

◆ dxfg_v4_endpoint_state_change_listener_t

typedef dxfg_endpoint_state_change_listener_t dxfg_v4_endpoint_state_change_listener_t

A handle of a Java PropertyChangeListener object that reports the state changes of an endpoint; release it with dxfg_JavaObjectHandler_release().

The listener calls a dxfg_endpoint_state_change_listener_func when the state of an endpoint to which it is added changes. Create it with dxfg_PropertyChangeListener_new() and add it with dxfg_DXEndpoint_addStateChangeListener(). The last handle of the listener that is released deactivates the listener: its function is not called anymore.

◆ dxfg_v4_endpoint_state_t

typedef dxfg_endpoint_state_t dxfg_v4_endpoint_state_t

The state of an endpoint, see dxfg_DXEndpoint_getState().

An endpoint is created DXFG_ENDPOINT_STATE_NOT_CONNECTED, unless it connects on creation (see dxfg_DXEndpoint_Builder_build()). dxfg_DXEndpoint_connect() makes it DXFG_ENDPOINT_STATE_CONNECTING, the established connection makes it DXFG_ENDPOINT_STATE_CONNECTED, a lost network connection returns it to DXFG_ENDPOINT_STATE_CONNECTING. DXFG_ENDPOINT_STATE_CLOSED is the final state.

Java: DXEndpoint.State.

◆ dxfg_v4_DXEndpoint_addStateChangeListener()

int32_t dxfg_v4_DXEndpoint_addStateChangeListener ( graal_isolatethread_t * thread,
dxfg_v4_endpoint_t * endpoint,
dxfg_v4_endpoint_state_change_listener_t * listener )

Adds the state change listener (see dxfg_v4_PropertyChangeListener_new()).

The state changes are delivered by a single task on the endpoint's executor that reports the change from the last reported state to the current one, so the fast changes are coalesced (e.g. DXFG_ENDPOINT_STATE_NOT_CONNECTED -> DXFG_ENDPOINT_STATE_CONNECTED without DXFG_ENDPOINT_STATE_CONNECTING). A notification may come after dxfg_v4_DXEndpoint_close() or dxfg_v4_DXEndpoint_removeStateChangeListener() returns.

The listener stays added until it is removed with dxfg_v4_DXEndpoint_removeStateChangeListener(); releasing the last handle of the listener only deactivates it.

Java: DXEndpoint.addStateChangeListener(PropertyChangeListener).

Parameters
[in]threadThe current GraalVM Isolate's thread.
[in]endpointThe endpoint.
[in]listenerThe listener. The caller keeps its handle.
Returns
DXFG_EXECUTE_SUCCESSFULLY (0) on successful function execution or DXFG_EXECUTE_FAIL (-1) on error. Use dxfg_v4_get_and_clear_thread_exception() to determine if an exception was thrown.

◆ dxfg_v4_DXEndpoint_awaitNotConnected()

int32_t dxfg_v4_DXEndpoint_awaitNotConnected ( graal_isolatethread_t * thread,
dxfg_v4_endpoint_t * endpoint )

Waits until the state of the endpoint becomes DXFG_ENDPOINT_STATE_NOT_CONNECTED or DXFG_ENDPOINT_STATE_CLOSED.

It is the signal that the files opened with dxfg_v4_DXEndpoint_connect() (file:... addresses) were finished reading, but not necessarily completely processed by the subscription listeners. Call dxfg_v4_DXEndpoint_closeAndAwaitTermination() after it returns to make sure that all the processing has completed.

The function blocks the calling thread. With a single-threaded executor of the endpoint, do not call it from the executor's thread (e.g. from a listener): it would wait forever.

◆ dxfg_v4_DXEndpoint_close()

int32_t dxfg_v4_DXEndpoint_close ( graal_isolatethread_t * thread,
dxfg_v4_endpoint_t * endpoint )

Closes the endpoint: disconnects it and releases its resources. The endpoint cannot be used after that.

The state of the endpoint becomes DXFG_ENDPOINT_STATE_CLOSED immediately.

The function does not wait for the notifications that are already scheduled: a state change listener (including the change to DXFG_ENDPOINT_STATE_CLOSED) or an event listener may still be called after it returns. Use dxfg_v4_DXEndpoint_closeAndAwaitTermination() to wait for them, or dxfg_v4_JavaObjectHandler_release() of the listener to stop its calls (see dxfg_v4_JavaObjectHandler_release()).

int32_t dxfg_v4_DXEndpoint_connect ( graal_isolatethread_t * thread,
dxfg_v4_endpoint_t * endpoint,
const char * address )

Connects the endpoint to the remote address.

The previously established connections are closed if the new address is different from the old one. The function does nothing if the address does not change or if the endpoint is closed. Otherwise, the state of the endpoint immediately becomes DXFG_ENDPOINT_STATE_CONNECTING.

The function does not wait until the connection is established: it is established asynchronously. It waits only until the state change listeners have processed the change to DXFG_ENDPOINT_STATE_CONNECTING.

The address string comes with the market data vendor agreement, for example host:port to connect to a server with TCP/IP, or :port to listen for a connection. A malformed address or a NULL address is an error. For the services that require credentials call dxfg_v4_DXEndpoint_user() and dxfg_v4_DXEndpoint_password() first.

Terminates all the network connections of the endpoint and initiates connecting again with the same address.

It works like dxfg_v4_DXEndpoint_disconnect() followed by dxfg_v4_DXEndpoint_connect() with the current address, but the internal resources may be reused. A connection with several target addresses tries to switch to an alternative address; the configured reconnect timeouts apply.
