◆ dxfg_v4_feed_event_listener_function

typedef dxfg_feed_event_listener_function dxfg_v4_feed_event_listener_function

The function of a dxfg_feed_event_listener_t: called when events are received.

The function is called by a thread of the executor of the subscription (the default executor of the feed's endpoint, or the executor set by dxfg_DXFeedSubscription_setExecutor()), not by the thread that added the listener. The calls for one subscription do not overlap: the next batch of events is passed after the function returns for the previous one. The number of events in a batch is limited by the events batch limit (see dxfg_DXFeedSubscription_setEventsBatchLimit()).

The list and the events belong to the SDK: it frees them (with their strings) after the function returns. Do not release them, copy what you need to keep.

Java: DXFeedEventListener.eventsReceived(List).

Parameters
[in]threadThe current GraalVM Isolate's thread.
[in]eventsThe received events.
[in]user_dataThe pointer that was passed to dxfg_DXFeedEventListener_new(); the SDK does not use it.

typedef dxfg_time_series_subscription_t dxfg_v4_time_series_subscription_t

A handle of a Java DXFeedTimeSeriesSubscription object; release it with dxfg_JavaObjectHandler_release().

A time series subscription is a subscription (dxfg_subscription_t) for the events that are time series: pass &sub->sub to the functions of this header. dxfg_v4_subscription_t * sub,
dxfg_v4_observable_subscription_change_listener_t * listener )

Adds the change listener to the subscription.

Create the listener with dxfg_v4_ObservableSubscriptionChangeListener_new(). If the listener was not added yet, is added to an open subscription and the subscription has symbols, the listener is notified immediately of the existing symbols (its symbolsAdded function) on the calling thread before the function returns. After that it is notified of every change on the thread that changes the subscription. The calls of the listener for one subscription do not overlap. Adding a listener that is already added, or to a closed subscription, does nothing.

◆ dxfg_v4_DXFeedSubscription_close()

int32_t dxfg_v4_DXFeedSubscription_close ( graal_isolatethread_t * thread,
dxfg_v4_subscription_t * sub )

Closes the subscription and makes it permanently detached from all feeds.

The subscription removes all its event listeners and change listeners and does not accept new ones. Every change listener is notified of the close (its subscriptionClosed function, see dxfg_v4_ObservableSubscriptionChangeListener_new()) on the calling thread before the function returns. The handle is not released: release it with dxfg_v4_JavaObjectHandler_release(). Closing a closed subscription does nothing.

An event listener may still receive one more batch of events after the function returns. To be sure that its function is not called anymore, release the listener (dxfg_v4_JavaObjectHandler_release()) or deactivate it (dxfg_v4_NativeListener_deactivate()).

Parameters
[in]threadThe current GraalVM Isolate's thread.
[in]subThe subscription handle.
Returns
DXFG_EXECUTE_SUCCESSFULLY (0) on successful function execution or DXFG_EXECUTE_FAIL (-1) on error. Use dxfg_v4_get_and_clear_thread_exception() to determine if an exception was thrown.

Java: DXFeedSubscription.close().
