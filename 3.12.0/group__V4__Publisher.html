typedef dxfg_java_object_handler dxfg_v4_java_object_handler

The handle of a Java object: the reference by which the C code refers to an object that lives in Java.

The handle is allocated by the SDK and owned by the caller: release it with dxfg_JavaObjectHandler_release(), which frees the structure and drops the reference to the Java object. As long as any handle of an object exists, the object is not garbage collected. Use dxfg_JavaObjectHandler_clone() to get another handle of the same object.

The typed handle structures (e.g. dxfg_executor_t, dxfg_time_zone_t) consist of this structure only (the field handler), so a pointer to a typed handle is passed to the functions that take a dxfg_java_object_handler * as &typed->handler (or by a cast).

Use dxfg_Object_toString() to get the string representation of the object, dxfg_Object_equals() to compare objects and dxfg_Object_hashCode() to get the hash code.

◆ dxfg_v4_observable_subscription_t

typedef dxfg_observable_subscription_t dxfg_v4_observable_subscription_t

A handle of a Java ObservableSubscription object; release it with dxfg_JavaObjectHandler_release().

It is the observable set of the symbols that the feeds are subscribed to, for one event type. Get it with dxfg_DXPublisher_getSubscription(). The subscription is closed when the endpoint of the publisher is closed.

int32_t dxfg_v4_DXPublisher_getInstance ( graal_isolatethread_t * thread,
DXFG_OUT dxfg_v4_publisher_t ** publisher )

Returns the default application-wide singleton publisher (DXPublisher.getInstance()): the publisher of the default endpoint with the publisher role. It is configured by the system properties (see dxfg_system_set_property()) when it is first used.

All callers share this publisher and its endpoint: closing the endpoint closes it for everyone in the process.

◆ dxfg_v4_DXPublisher_getSubscription()

int32_t dxfg_v4_DXPublisher_getSubscription ( graal_isolatethread_t * thread,
dxfg_v4_publisher_t * publisher,
dxfg_v4_event_clazz_t eventClazz,
DXFG_OUT dxfg_v4_observable_subscription_t ** subscription )

Returns the observable set of the subscribed symbols for the event type.

The symbols of the set are the symbols that the feeds are subscribed to; the set contains the wildcard symbol if there is a subscription to all symbols, and, for a time series subscription, the symbols wrapped with the time of the subscription (dxfg_v4_time_series_subscription_symbol_t). The set may notify its change listeners of the same symbols several times without a removal between the notifications: it happens when the subscription disappears, the cached data is lost and the subscription appears again. On each such notification the data provider is to publish the most recent events of the symbols (dxfg_v4_DXPublisher_publishEvents()).

◆ dxfg_v4_DXPublisher_publishEvents()

int32_t dxfg_v4_DXPublisher_publishEvents ( graal_isolatethread_t * thread,
dxfg_v4_publisher_t * publisher,
dxfg_v4_event_type_list * events )

Publishes the events to the corresponding feeds.

If the endpoint of the publisher has the publisher role and is connected, the events are delivered to the remote endpoints. The local feed of the endpoint always receives them. A feed receives an event only if it is subscribed to its symbol (or to all symbols with a wildcard, or, for a time series event, with a time series subscription for the time of the event). The published events are not stored and are lost if there is no subscription; the last events of the lasting event types are kept while the subscription to their symbol exists.

The events are serialized by the function: the list and the events are only read, the caller keeps its ownership and can reuse or release them after the function returns.

[in]publisherThe publisher handle.
[in]eventsThe events to publish.

◆ dxfg_v4_ObservableSubscription_addChangeListener()

int32_t dxfg_v4_ObservableSubscription_addChangeListener ( graal_isolatethread_t * thread,
dxfg_v4_observable_subscription_t * sub,
dxfg_v4_observable_subscription_change_listener_t * listener )

Adds the change listener to the observable subscription.

Create the listener with dxfg_v4_ObservableSubscriptionChangeListener_new(); see its description for the callbacks of the listener: they are called on a Java thread, not necessarily the one that added the listener, and the symbols belong to the SDK. If the listener is added to an open subscription, it is notified immediately of the existing subscription state (its symbolsAdded function) before the function returns, and after that of every change. The calls of the listener for one subscription do not overlap. Adding a listener that is already added, or to a closed subscription, does nothing.

[in]threadThe current GraalVM Isolate's thread.
[in]subThe observable subscription handle.

To be sure that the functions of the listener are not called anymore, release it (dxfg_v4_JavaObjectHandler_release()) or deactivate it (dxfg_v4_NativeListener_deactivate()).
