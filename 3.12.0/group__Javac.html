Detailed Description

Java helper types and functions that every other header uses: object handles, lists, strings, executors, time zones, time periods and formats, authorization tokens.

This group is the reference for the ownership rules of the C API:

  • A Java object that a function returns is returned as a handle (dxfg_java_object_handler, or a typed handle structure that contains it, e.g. dxfg_executor_t). The handle is allocated by the SDK and owned by the caller: release it with dxfg_JavaObjectHandler_release(). A handle keeps its Java object alive.
  • A string (const char *) that a function returns is allocated by the SDK and owned by the caller: release it with dxfg_String_release(). A string that is a field of a structure belongs to that structure and is freed with it.
  • A list that a function returns is allocated by the SDK together with its array of elements and the elements: release it with dxfg_CList_String_release() (dxfg_string_list) or dxfg_CList_JavaObjectHandler_release() (dxfg_java_object_handler_list).
  • The value returned on error is given in the @return of each function and differs between functions. In this header a function that returns int32_t status returns DXFG_EXECUTE_SUCCESSFULLY (0) or DXFG_EXECUTE_FAIL (-1) on error, and a function that returns a pointer returns NULL on error. A function of this header that returns data as int32_t, like dxfg_Object_equals() or dxfg_TimeZone_getRawOffset(), returns INT32_MIN (-2147483648) on error. dxfg_get_and_clear_thread_exception_t() gives the exception.

◆ dxfg_java_object_handler

typedef struct dxfg_java_object_handler dxfg_java_object_handler

The handle of a Java object: the reference by which the C code refers to an object that lives in Java.

The handle is allocated by the SDK and owned by the caller: release it with dxfg_JavaObjectHandler_release(), which frees the structure and drops the reference to the Java object. As long as any handle of an object exists, the object is not garbage collected. Use dxfg_JavaObjectHandler_clone() to get another handle of the same object.

The typed handle structures (e.g. dxfg_executor_t, dxfg_time_zone_t) consist of this structure only (the field handler), so a pointer to a typed handle is passed to the functions that take a dxfg_java_object_handler * as &typed->handler (or by a cast).

Use dxfg_Object_toString() to get the string representation of the object, dxfg_Object_equals() to compare objects and dxfg_Object_hashCode() to get the hash code.

typedef enum dxfg_rounding_mode_t dxfg_rounding_mode_t

The rounding behavior of numerical operations that can discard precision (java.math.RoundingMode), e.g. of dxfg_PriceIncrements_roundPrice3().

Specifies a rounding behavior for numerical operations capable of discarding precision. Each rounding mode indicates how the least significant returned digit of a rounded result is to be calculated. If fewer digits are returned than the digits needed to represent the exact numerical result, the discarded digits will be referred to as the discarded fraction regardless the digits' contribution to the value of the number. In other words, considered as a numerical value, the discarded fraction could have an absolute value greater than one.

DXFG_ROUNDING_MODE_HALF_EVEN 

Rounding mode to round towards the "nearest neighbor" unless both neighbors are equidistant, in which case, round towards the even neighbor. Behaves as for DXFG_ROUNDING_MODE_HALF_UP if the digit to the left of the discarded fraction is odd; behaves as for DXFG_ROUNDING_MODE_HALF_DOWN if it's even. Note that this is the rounding mode that statistically minimizes cumulative error when applied repeatedly over a sequence of calculations. It is sometimes known as "Banker's rounding" and is chiefly used in the USA. This rounding mode is analogous to the rounding policy used for float and double arithmetic in Java.

Parses the date and the time from the string in an ISO 8601 format. The string can be:
