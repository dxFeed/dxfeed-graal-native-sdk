Wrapper guide

This guide is the contract between the SDK and a wrapper: a library that makes the C API usable from another language (Python, Go, .NET, Rust, Swift, Java through FFM, ...). It states what a wrapper may rely on and what it must do, in one place; the groups of the C API reference hold the details, and the pages link to them instead of repeating them. The rules of the dxfg_v4_ functions themselves are in The v4 functions.

  • Threads – attaching the threads of the wrapper's runtime, long-lived threads, finalizers.
  • Ownership and lifetimes – who owns what a function returns, and when it is released.
  • Return codes and outcomes – the return codes, the exceptions and the outcomes of the functions that wait.
  • Tiers and versioning – the tiers, the start-up check, the features and the API description.
  • Delivery of data – which delivery of data to use for what.
  • The conformance kit – what the conformance kit proves about a wrapper, and what it cannot.

A wrapper that follows these pages and passes the kit in strict mode on every platform it supports is conformant for what the kit covers; the limits are on The conformance kit.
