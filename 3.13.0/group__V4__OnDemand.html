typedef dxfg_java_object_handler dxfg_v4_java_object_handler

The handle of a Java object: the reference by which the C code refers to an object that lives in Java.

The handle is allocated by the SDK and owned by the caller: release it with dxfg_JavaObjectHandler_release(), which frees the structure and drops the reference to the Java object. As long as any handle of an object exists, the object is not garbage collected. Use dxfg_JavaObjectHandler_clone() to get another handle of the same object.

The typed handle structures (e.g. dxfg_executor_t, dxfg_time_zone_t) consist of this structure only (the field handler), so a pointer to a typed handle is passed to the functions that take a dxfg_java_object_handler * as &typed->handler (or by a cast).

Use dxfg_Object_toString() to get the string representation of the object, dxfg_Object_equals() to compare objects and dxfg_Object_hashCode() to get the hash code.

A handle of a Java OnDemandService object; release it with dxfg_JavaObjectHandler_release().

One service is associated with each endpoint that has the role DXFG_ENDPOINT_ROLE_FEED or DXFG_ENDPOINT_ROLE_ON_DEMAND_FEED: get it with dxfg_OnDemandService_getInstance() or dxfg_OnDemandService_getInstance2(). Releasing the handle does not stop the replay and does not close the endpoint.

◆ dxfg_v4_OnDemandPropertyChangeListener_function

typedef void(*) dxfg_v4_OnDemandPropertyChangeListener_function(graal_isolatethread_t *thread, const char *property_name, const dxfg_v4_on_demand_property_value_t *old_value, const dxfg_v4_on_demand_property_value_t *new_value, void *user_data)

The callback of a listener of the property changes of an on-demand service.

The service calls it once per changed property: replaySupported, replay, clear (booleans), speed (a double) and time (a time). It is called on a thread of the executor of the endpoint of the service, not on the thread that changed the service, with no lock of the SDK held: the callback may add and remove listeners. The changes of one service are reported one at a time.

The name and the values belong to the SDK and are valid only until the function returns.

Parameters
[in]threadThe current GraalVM Isolate's thread.
[in]property_nameThe name of the property, a NUL-terminated UTF-8 string (NULL if the service reports a change of several properties at once, as a Java property change event without a name may do).
[in]old_valueThe old value of the property.
[in]new_valueThe new value of the property.
[in]user_dataThe user data passed to dxfg_v4_OnDemandPropertyChangeListener_new().
Since
3.13.0

◆ dxfg_v4_OnDemandService_getInstance()

int32_t dxfg_v4_OnDemandService_getInstance ( graal_isolatethread_t * thread,
DXFG_OUT dxfg_v4_on_demand_service_t ** onDemandService )

Returns the on-demand service of the default endpoint with the DXFG_ENDPOINT_ROLE_ON_DEMAND_FEED role.

The endpoint is the application-wide default endpoint of that role (dxfg_v4_OnDemandService_getEndpoint() returns it; dxfg_v4_DXEndpoint_getInstanceWithRole() creates a new endpoint instead), which is not connected to any other real-time or delayed data feed. It is created on the first call, is configured by the system properties and is closed by dxfg_v4_system_close_all_and_await_termination(). To switch another feed to the replay and back, use dxfg_v4_OnDemandService_getInstanceByEndpoint() with the endpoint of that feed.

The call fails if the on-demand implementation is not available in the library.

Turns the replay mode on from the specified time with the specified speed.

The feed is disconnected from the other data providers, pre-buffers the historical tick data and replays it as if it came from the data feeds now. After the call dxfg_v4_OnDemandService_isReplay() returns 1, dxfg_v4_OnDemandService_isClear() returns 0, dxfg_v4_OnDemandService_getTime() returns the time that is being replayed and dxfg_v4_OnDemandService_getSpeed() returns speed. The call fails if the replay mode is not supported (see dxfg_v4_OnDemandService_isReplaySupported()) or if the speed is negative.

Java: OnDemandService.replay(Date, double).

int32_t dxfg_v4_OnDemandService_stopAndClear ( graal_isolatethread_t * thread,
dxfg_v4_on_demand_service_t * service )

Stops the incoming data and clears it without resuming the data updates.

The call works both in the replay mode and for the ordinary data feed: all the incoming data updates are suspended and the current data is cleared. After the call dxfg_v4_OnDemandService_isReplay() returns 0, dxfg_v4_OnDemandService_isClear() returns 1, dxfg_v4_OnDemandService_getTime() returns the last replayed time and dxfg_v4_OnDemandService_getSpeed() returns 0. The ordinary feed is resumed by dxfg_v4_OnDemandService_stopAndResume(), the replay is continued by dxfg_v4_OnDemandService_replay() or dxfg_v4_OnDemandService_replayWithSpeed().

Stops the replay and resumes the ordinary data feed.

The call has no effect if the service is neither in the replay mode nor in the clear mode. After the call dxfg_v4_OnDemandService_isReplay() and dxfg_v4_OnDemandService_isClear() return 0, dxfg_v4_OnDemandService_getTime() returns the last replayed time and dxfg_v4_OnDemandService_getSpeed() returns 0. An endpoint with the role DXFG_ENDPOINT_ROLE_ON_DEMAND_FEED has no ordinary feed, so for it the call works like dxfg_v4_OnDemandService_stopAndClear().
