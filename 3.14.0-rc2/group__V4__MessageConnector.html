Detailed Description

The message connectors of an endpoint: their state, addresses and statistics.

An endpoint connected with dxfg_v4_DXEndpoint_connect() has one message connector per address of the address string (e.g. two for (host1:7300)(host2:7300)): a client socket connector for host:port, a server socket connector for :port, or another kind (a file, a non-blocking or a custom connector). dxfg_v4_DXEndpoint_getConnectors() returns the current connectors of the endpoint; each call reads them anew. A connect to another address replaces the connectors: the new list has new connectors, and a replaced one still answers, as DXFG_V4_MESSAGE_CONNECTOR_STATE_DISCONNECTED. A connect to the same address and dxfg_v4_DXEndpoint_reconnect() keep the connectors.

Each value of a connector is current when it is read; the values are not read together as one consistent set. Reading them changes nothing: the statistics are not reset, and other readers (QD's JMX beans) see the same values.

A connector handle is released with dxfg_v4_JavaObjectHandler_release() and a list of them with dxfg_v4_message_connector_list_release(); dxfg_v4_JavaObjectHandler_clone() keeps a connector of a list after the list is released. The handles and the lists can be released in any order, also after the endpoint is closed.

A listener (dxfg_v4_MessageConnectorListener_new(), experimental) added to an endpoint with dxfg_v4_DXEndpoint_addMessageConnectorListener() is called after the state changes of its connectors, also of the connectors that a later connect creates.

The last connection error of a connector (dxfg_v4_MessageConnector_getLastError(), experimental) and of an endpoint (dxfg_v4_DXEndpoint_getLastConnectionError()) tells why a connect failed or a connection dropped: the time, the address, a category (DXFG_V4_CONNECTION_ERROR_CONNECT_FAILED and others), the exception and its message. The SDK captures the errors from the log records of QD's default logging (java.util.logging), whether or not a logging listener is set and at any log.level. With another log.className nothing is captured, and a level the user sets on QD's loggers com.devexperts.qd.qtp.MessageConnector, com.devexperts.qd.qtp.MessageAdapterConnection or com.devexperts.connector.codec.ssl themselves wins and may stop the capture.

DXFG_V4_FEATURE_MESSAGE_CONNECTORS reports the functions of the group except the connection errors, which DXFG_V4_FEATURE_CONNECTION_ERRORS reports.

Java: com.devexperts.qd.qtp.MessageConnector of com.dxfeed.api.impl.DXEndpointImpl.getQDEndpoint().

◆ dxfg_v4_message_connector_listener_func

typedef void(*) dxfg_v4_message_connector_listener_func(graal_isolatethread_t *thread, dxfg_v4_message_connector_t *connector, void *user_data)

The function of a listener of the state changes of the message connectors of an endpoint (dxfg_v4_MessageConnectorListener_new()).

It is called after the state of a connector of an endpoint to which the listener is added has changed: it connected, lost its connection, started to reconnect, or was replaced or closed. The function reads the current values of the connector (dxfg_v4_MessageConnector_getState() and the other getters); fast changes of one connector may come as one call. It is called on one thread of the SDK for all the listeners of the isolate (named dxfg-MessageConnectorListener), never on a QD thread and never within the call that changes the state (e.g. dxfg_v4_DXEndpoint_connect()), one call at a time. The function may call any function of the SDK on that thread, including dxfg_v4_DXEndpoint_connect() of its endpoint, the getters of the connector and the release of its own listener; it should return quickly, since the next call waits for it. When the change is a connection error, the error is recorded before the call: dxfg_v4_MessageConnector_getLastError() returns it in the call already.

Parameters
[in]threadThe current GraalVM Isolate's thread (the thread of the SDK that calls the function).
[in]connectorThe connector whose state changed. The handle is valid during the call only and is released by the SDK; dxfg_v4_JavaObjectHandler_clone() keeps the connector after the call.
[in]user_dataThe user data given to dxfg_v4_MessageConnectorListener_new().
Experimental
It may change or be removed in a minor release, see The v4 functions.
Since
3.14.0

◆ dxfg_v4_DXEndpoint_getLastConnectionError()

int32_t dxfg_v4_DXEndpoint_getLastConnectionError ( graal_isolatethread_t * thread,
dxfg_v4_endpoint_t * endpoint,
DXFG_OUT dxfg_v4_connection_error_t ** error )

Returns the last connection error of an endpoint: the newest error of all its connectors.

The error stays after a connect to another address replaced the connector that recorded it, and after the endpoint is closed; a successful connection clears nothing.

Read the error in the connector listener (dxfg_v4_DXEndpoint_addMessageConnectorListener()), which is called after the error is recorded. The state change listener of the endpoint (dxfg_v4_DXEndpoint_addStateChangeListener()) gives no such order: QD computes the endpoint state on another thread, so the listener may be called before the error of that change is recorded; compare the time or the count of the error with those seen before. Failed connect attempts do not change the endpoint state at all: the endpoint stays connecting between them.

Java: no counterpart; the SDK captures the errors from QD's log records.

Parameters
[in]threadThe current GraalVM Isolate's thread.
[in]endpointThe endpoint; must not be NULL.
[out]errorThe pointer to the variable that receives the error (release it with dxfg_v4_ConnectionError_release()), or NULL when the endpoint has had no error; must not be NULL. It is written on success only.
Returns
DXFG_EXECUTE_SUCCESSFULLY (0) on successful function execution or DXFG_EXECUTE_FAIL (-1) on error. Use dxfg_v4_get_and_clear_thread_exception() to determine if an exception was thrown.
Experimental
It may change or be removed in a minor release, see The v4 functions.

◆ dxfg_v4_MessageConnectorListener_new()

dxfg_v4_message_connector_listener_func user_func,
void * user_data,
DXFG_OUT dxfg_v4_message_connector_listener_t ** listener )

Creates a new listener of the state changes of the message connectors of an endpoint.

The listener does nothing until it is added to an endpoint with dxfg_v4_DXEndpoint_addMessageConnectorListener(). The function is called as described at dxfg_v4_message_connector_listener_func.

Releasing the last handle of the listener with dxfg_v4_JavaObjectHandler_release() (or dxfg_v4_NativeListener_deactivate(), or dxfg_v4_NativeListener_deactivateAll()) stops the calls of the function: after the release returns the function is not running (except on the releasing thread itself, when the function releases its own listener) and is not called anymore, so the user data can be freed. A released listener that is still added removes itself from the endpoint at the next state change of a connector.

Java: com.devexperts.qd.qtp.MessageConnectorListener.stateChanged(MessageConnector), called on a thread of the SDK.

Parameters
[in]threadThe current GraalVM Isolate's thread.

[out]listenerThe pointer to the variable that receives the listener (release its handle with dxfg_v4_JavaObjectHandler_release()); must not be NULL. It is written on success only.
