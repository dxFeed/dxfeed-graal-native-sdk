Detailed Description

The filter of the subscriptions and the events by named categories of QD filter expressions.

A builder (dxfg_v4_DXFeedFilter_newBuilder()) takes the categories of a filter, each one a name and a QD filter expression (e.g. IBM,AAPL, A*, range-A-M-, ipf[file.ipf,update=10m]), and builds the filter (dxfg_v4_DXFeedFilter_Builder_build()). The filter tells whether a subscription (an event type and a symbol) or an event passes any of its categories, and which category is the first one that it passes, in the order the categories were added.

A filter does not change. A dynamic filter (dxfg_v4_DXFeedFilter_isDynamic()), e.g. one with an ipf[...] expression with an update period, gets a new version on each update: its tracker (dxfg_v4_DXFeedFilter_getTracker()) returns the latest version (dxfg_v4_DXFeedFilterTracker_getCurrentFilter()) and calls its listeners (dxfg_v4_DXFeedFilterListener_new()) after each update.

Each function that returns a handle returns a new one, which the caller releases with dxfg_v4_JavaObjectHandler_release(). The builder, the filter, the tracker and the listener can be released in any order.

All the functions and types of the group are experimental (see The v4 functions): the Java API they call is @Experimental in QD and may change. DXFG_V4_FEATURE_FEED_FILTER reports them.

Java: com.dxfeed.api.DXFeedFilter, DXFeedFilter.Builder, DXFeedFilterTracker, DXFeedFilterListener.

◆ dxfg_v4_feed_filter_listener_func

typedef void(*) dxfg_v4_feed_filter_listener_func(graal_isolatethread_t *thread, void *user_data)

The function of a listener of the updates of a feed filter (dxfg_v4_DXFeedFilterListener_new()).

It is called after the filter of a tracker to which the listener is added has been updated; the tracker returns the new version with dxfg_v4_DXFeedFilterTracker_getCurrentFilter(). Fast updates may come as one call. It is called on a thread of the SDK that updates the filter (e.g. the thread that reloads the IPF of an ipf[...] expression), never on the thread that adds the listener. The function may call any function of the SDK on that thread, including dxfg_v4_DXFeedFilterTracker_addListener() and dxfg_v4_DXFeedFilterTracker_removeListener() of its own tracker and the release of its own listener; it should return quickly, since the next update waits for it.

Parameters
[in]threadThe current GraalVM Isolate's thread (the thread of the SDK that calls the function).
[in]user_dataThe user data given to dxfg_v4_DXFeedFilterListener_new().

dxfg_v4_feed_filter_listener_func user_func,
void * user_data,
DXFG_OUT dxfg_v4_feed_filter_listener_t ** listener )

Creates a new listener of the updates of a feed filter.

The listener does nothing until it is added to a tracker with dxfg_v4_DXFeedFilterTracker_addListener(). The function is called as described at dxfg_v4_feed_filter_listener_func, with the user data only: it gets no handles.

Releasing the last handle of the listener with dxfg_v4_JavaObjectHandler_release() (or dxfg_v4_NativeListener_deactivate(), or dxfg_v4_NativeListener_deactivateAll()) stops the calls of the function: after the release returns the function is not running (except on the releasing thread itself, when the function releases its own listener) and is not called anymore, so the user data can be freed. A released listener that is still added removes itself from the tracker at its next update; until then the tracker keeps following the updates (e.g. reloads the IPF file), so remove the listener before the release to stop at once.

Java: DXFeedFilterListener.filterUpdated(DXFeedFilterTracker).

[in]user_funcThe function to call after the updates; must not be NULL.
[in]user_dataThe user data to pass to the function; the SDK does not use it. It must stay valid until the listener is deactivated.
[out]listenerThe pointer to the variable that receives the listener (release its handle with dxfg_v4_JavaObjectHandler_release()); must not be NULL. It is written on success only.
Returns
